## Rueckfrage D23 (lastP1-Cache, detect.js:1924-1929): Einordnung
Der Cache ist eine Modul-Closure, haelt Text und Treffer der letzten Analyse bis zum naechsten abweichenden Text, ist ueber die Oberflaeche nicht erreichbar: reine Speicherretention, wie D23 sagt. Er ist von S2 (prj, prjRes, Marks ueber die Oberflaeche erreichbar) sauber abzugrenzen; D23 sollte das im Protokoll ausdruecklich festhalten. Geschwister (aus Code gelesen, nicht gelaufen): clearAll() (privacy-shield.html:3762) setzt aiCache nicht zurueck (Text als key + Spans, nur an :2339/:3184/:3275 geleert); die UI sagt "existiert nur im RAM, wird nach Sitzung geloescht" (:1867): JavaScript kann RAM nicht zusichern nullen (unveraenderliche Strings, GC), die Aussage sollte "nicht gespeichert, nur im Arbeitsspeicher" lauten. Vorschlag klein (S): PSDetect.resetCache() plus aiCache-Reset in clearAll und Sitzungsende, kein Versprechen der Nullung; Dringlichkeit niedrig, gemeinsam mit dem S2-Paket.
